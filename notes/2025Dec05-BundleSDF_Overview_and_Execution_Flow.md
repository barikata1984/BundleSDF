# BundleSDF リポジトリ概要と実行フロー

## 1. リポジトリの概要: BundleSDF

**BundleSDF** (Neural 6-DoF Tracking and 3D Reconstruction of Unknown Objects) は、CVPR 2023で発表された、単眼RGB-Dビデオから**未知の物体の6自由度（6-DoF）追跡**と**3D再構成**を同時に行う手法の実装です。

*   **主な特徴**:
    *   **未知の物体に対応**: 事前のCADモデルを必要としません。最初のフレームでセグメンテーション（マスク）が与えられれば動作します。
    *   **Neural Object Field**: 物体の形状と外観を表現するために、NeRF（Neural Radiance Fields）ベースの表現（Neural Object Field）を学習します。
    *   **Pose Graph Optimization**: 特徴点マッチングによる幾何学的な追跡と、NeRFによる最適化を並行して行い、ロバストな追跡を実現します。
    *   **Memory Pool**: キーフレームを動的に管理し、追跡スレッドとNeRFスレッド間で情報を共有します。

## 2. `run_custom.py` (run_videoモード) の実行フロー詳細

`python run_custom.py --mode run_video ...` を実行した際の処理の流れは以下のようになります。

### A. 初期化フェーズ (`run_one_video` 関数)

1.  **設定のロード**:
    *   `BundleTrack/config_ho3d.yml` (トラッキング用設定) と `config.yml` (NeRF用設定) を読み込みます。
    *   出力フォルダの作成や、設定値（デバッグレベル、浸食処理など）の上書きを行います。

2.  **トラッカーの初期化**:
    *   `BundleSdf` クラスのインスタンスを作成します。
    *   この際、**GUIプロセス** (`run_gui`) と **NeRF学習プロセス** (`run_nerf`) が別プロセス/スレッドとして起動し、待機状態に入ります。

3.  **データリーダーの準備**:
    *   `YcbineoatReader` (または類似のリーダー) を使用して、指定されたビデオディレクトリからRGB画像、深度画像、マスク画像のパスを取得します。

### B. メインループ: フレームごとの処理

ビデオの各フレームに対して以下の処理が順番に行われます。

1.  **データの読み込み**:
    *   RGB画像、深度画像を読み込み、リサイズします。
    *   マスク画像を取得します（ファイルから読み込むか、`Segmenter` (XMem等) を使用して推論します）。

2.  **トラッキング実行 (`tracker.run`)**:
    `BundleSdf.run()` メソッドが呼び出され、以下の処理が行われます。

    *   **フレーム作成 (`make_frame`)**:
        *   C++側の `Frame` オブジェクトを作成し、画像データを保持させます。
    *   **前処理**:
        *   深度画像のデノイズ処理などを行います。
    *   **ポーズ推定と最適化 (`process_new_frame`)**:
        *   **特徴点マッチング**: 現在のフレームと過去のキーフレーム（または直前のフレーム）との間で、`LoFTR` (Deep Learningベースの特徴点マッチャー) を用いて対応点 (`corres`) を探索します。
        *   **ポーズ初期化**: 対応点を用いて、現在のフレームの初期ポーズを推定します。
        *   **Pose Graph Optimization**: `bundler.optimizeGPU` を呼び出し、バンドル調整（Bundle Adjustment）を行い、幾何学的な整合性が取れるようにポーズを最適化します。
        *   **キーフレーム判定**: 現在のフレームが新しいキーフレームとして適しているか（移動量が大きい、新しい領域が見えている等）を判定し、キーフレームリストに追加します。

3.  **NeRFスレッドとの連携 (並列処理)**:
    *   新しいキーフレームが追加されると、そのデータ（RGB, Depth, Mask, Pose）が **NeRFプロセス (`run_nerf`)** に送信されます。
    *   **NeRFプロセス側**:
        *   送られてきたキーフレームを用いて、Neural Object Field (NeRF) を学習・更新します。
        *   NeRFのレンダリング誤差を最小化するように、**キーフレームのポーズ自体も微修正** (`optimized_cvcam_in_obs`) します。
        *   定期的にメッシュ (`mesh`) を抽出します。
    *   **同期**:
        *   NeRFプロセスでポーズが修正された場合、メインのトラッキングスレッドはその修正を受け取り、自身のキーフレームポーズを更新します（ループバック）。これにより、ドリフト（誤差の蓄積）を補正します。

4.  **結果の保存**:
    *   推定されたポーズ (`ob_in_cam`) やデバッグ情報が保存されます。

### C. 終了処理

1.  **プロセスの終了 (`tracker.on_finish`)**:
    *   全フレームの処理が終わると、GUIプロセスとNeRFプロセスを終了させます。
    *   最終的なポーズ情報を保存します。

2.  **グローバルリファインメント (オプション)**:
    *   `run_one_video_global_nerf` が呼び出され、全フレームのポーズが確定した状態で、再度NeRFを高解像度・高品質設定で学習し直し、最終的な高精細メッシュを生成します。

### まとめ

処理の流れは大きく分けて **「1. 逐次的なトラッキング（特徴点ベース）」** と **「2. バックグラウンドでのNeRF学習（3D形状とポーズの全体最適化）」** の2つが並走し、互いに情報をやり取りしながら進む構成になっています。
